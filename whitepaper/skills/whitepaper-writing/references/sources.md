# 外部写法出处

只放链接和可用规则，不转载全文。写廗点白皮书时引用规则，不把这些文章贴进正文。

## 可复用的 Skill

- kaynetik/skills `whitepapers/SKILL.md`（name: web3-whitepaper）：https://github.com/kaynetik/skills/blob/main/whitepapers/SKILL.md
  - 必须有问题与非目标、系统边界、威胁模型、代币只写功能不写收益、风险、可复现出处。
  - 禁止价格预测、ROI、未经核实的价值捕获、把未审计说成已审计。
- AionSystem/Whitepaper-Blueprint：https://github.com/AionSystem/Whitepaper-Blueprint
  - 先定文件类型（问题-方案 / 研究 / 技术规格），再写正文。廗点用问题-方案，不用行业报告体。

## 今天可对照的公开说法

- Robert Stone, 2026-10-07, How to Write a Crypto Whitepaper: https://defimarketjournal.com/markets/how-to-write-a-crypto-whitepaper.html
  - 顺序：问题、机制、代币能做什么、分配、路线图、团队、风险、法律声明。
  - 风险先写。不写价格承诺。团队用真名或说明为什么匿名。
  - 欧盟 MiCA 对公开发售有白皮书义务；廗点不发售，仍要写明不是要约、不保价值。
- X @StoneOnChain 2107851186149953648：上面那篇文章的转发，没有额外规则。
- X @thebillyboone 2103968360803561764：比特币白皮书 9 页，结构是问题、账本、谁有权写下一页、写入为什么贵。可作比特币更短，不能比它更空。
- X @trixventures 2107446685345669471：代币机制要让坏行为更贵、好行为能持续。廗点对应的是押金没收和任务上限，不是涨价。
- X @jayzinprospecs 2107590188310380651：核验证明的是「这次计算按已提交规范跑过」，不证明结论为真。廗点同样：证据哈希对得上，不证明审稿本身正确。

## 对照范本，不要抄

- Bitcoin: https://bitcoin.org/bitcoin.pdf — 9 页，先问题再机制。
- Uniswap v3 Core: https://uniswap.org/whitepaper-v3.pdf — 公式和边界写在一起。
