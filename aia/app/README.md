# 知行社 · AIA Commons · 真实科研协作

从两份 2026-10-07 下午对齐纪要落实的多人协作产品：保存自己的研究材料，请另一位用户审阅，再由执行者交付、独立核查者验收，形成可追查的贡献记录。主入口使用真实账号、服务端授权、SQLite 和原件归档。

社区三板、双模型配置、真实核对题、廌点及 Agent 授权的运行和升级说明见 [COMMUNITY_GUIDE.md](COMMUNITY_GUIDE.md)，机器接口见 [AGENT_GUIDE.md](AGENT_GUIDE.md)。

## 启动

需要 **Node.js 24.13.0+**。在仓库根目录：

```sh
npm ci
npm start
```

打开 <http://127.0.0.1:8890/workspace/>；站点首页现在进入队友的獬豸 UI <http://127.0.0.1:8890/ui/>。Windows 也可运行 `powershell -ExecutionPolicy Bypass -File aia/app/start-local.ps1`，在当前终端启动。保持终端运行，随后在浏览器打开网址；已经启动时直接打开网址，不重复启动服务。

首次启动的账号与私人研究为空，需要注册自己的账号；公开社区自动载入十道有来源的核对任务。没有预设密码、固定演示身份、虚构研究或初始余额。邀请同伴注册，在协作者搜索中通过用户名指定审阅人、执行者和核查者。单机验证可用不同浏览器配置或退出后分别登录。

## 实际使用路径

1. 注册账号，填写机构和个人资料；通过 OpenAlex 实时检索公开档案。支持中文姓名和 Lv／Lyu／Lu 等拼写扩展，候选按作者编号去重，部分网络失败明确提示。选择公开档案和手填 ORCID 均为用户声明；钱包签名只证明对该钱包的控制权。
2. 在 Idea 导入 PDF、文本或 ARA 目录。原件、生成材料、文件哈希和研究版本保存在服务端；修订产生新版本，已有任务绑定的旧版不会被覆盖。
3. 运行材料预检，逐项打开证据或下载原件。检查使用共享材料引擎的本地规则，不是外部大模型、创新性判定或官方 ARA Seal。
4. 邀请另一个账号完成 Attention 审阅，分别写创新性、方法、证据及局限。指定审阅人登录后提交；作者不能切换角色代审。
5. 创建 Action 时写明交付要求和验收条件，指定执行者与独立核查者。作者、执行者和核查者必须是三个不同账号。
6. 执行者领取任务，提交真实文件、工作报告及运行环境。核查者阅读交付，选择验收、返修或拒绝，同时单独记录研究结果是否一致。符合工作要求但结果不一致可以验收。
7. 验收形成唯一的贡献收据。返修重新交付，旧交付不能再被验收。贡献是有证据和验收人的工作事实；按任务类型在社区廌点账本记账，不代表可提现余额。

## 钱包与链

钱包关联采用一次性、限时、绑定账号和站点的签名挑战。用户在自己的钱包中确认后，服务端验证签名。内容存证由用户主动发起交易；服务端独立读取 RPC，核对网络、合约、发送人、调用参数、事件和成功状态，才显示确认。

个人档案声明也可存证：先填写 ORCID 或 OpenAlex 标识、签名关联钱包，再冻结当前资料快照发起 CLAIM。后续修改个人资料不会改变已准备的声明；该存证不是 ORCID 官方认证或论文归属审核。

- BOT 主网：677；仅在 `aia/chain/deployments/botchain.json` 有真实配置时可准备交易。仓库已包含主网配置，合约与部署交易见 [MAINNET.md](../chain/MAINNET.md)。
- BOT 测试网：968；使用仓库的 `botchain-testnet.json`。测试网记录明确标注测试网，不算主网交付。
- 文件摘要为 SHA-256；账号主题为 `keccak256("aia-user:" + userId)`；规则标签 `aia-v1-sha256`。完整材料继续受服务端权限保护。
- 登记合约是公开声明登记，不证明科学真实性或第三方认证；原始记录须与验收报告一起核对。

用户已确定使用 BOT／稳定币，具体网络、稳定币地址、价格、收款方、预存与退款规则仍待补充。本版不收款、不扣款、不承诺赏金；当前新建任务明确为无报酬协作。没有部署托管支付合约。

## 存储与部署

默认数据在本目录 `.runtime/`：SQLite 数据库、研究及交付文件、Windows 启动日志。该目录被 Git 忽略，不会随着推送上传用户材料或账号。旧原型 JSON 账本和浏览器存储不会自动迁入新账号。

| 环境变量 | 用途 |
|---|---|
| `PORT` | 默认 8890 |
| `AIA_BIND` | 默认 `127.0.0.1`；反向代理访问地址 |
| `AIA_APP_DATA_DIR` | 数据目录；服务器上建议使用绝对路径和持久磁盘 |
| `AIA_ORIGIN` | 公网部署必须配置，如 `https://research.example.org`，不带尾部斜杠 |
| `OPENALEX_API_KEY` | 可选；服务器向 OpenAlex 查询使用，不发送给网页 |
| `SCIVERSE_API_TOKEN` | 可选；服务器查询论文、语义段落及有权读取的原文和图表，不发送给网页 |
| `AIA_ADMIN_TOKEN` | 独立数据源管理口令，24–512 个字符；不设置时自动生成到数据目录的 `admin-access.txt` |

`npm start` 和 Windows 启动脚本自动读取本目录 `.env`（不存在时使用环境变量）。参考 `.env.example`，把 `OPENALEX_API_KEY` 配置在服务端；真实配置被 Git 忽略，也不在静态文件公开清单中。

首页 `/ui/` 使用 `/scholar-api/search` 实时查询 OpenAlex 作者库，支持姓名、中文拼音变体、ORCID 和作者编号。姓名查询后可选填学术单位：先匹配 OpenAlex 的单位名称、别名或简称，再以单位编号与姓名共同检索全库，避免只筛选首批候选。留空仍可继续；未识别单位时可清除条件，不代表研究者不存在。单位依据最近公开机构记录，可能缺失或滞后；ORCID／作者编号的精确查询优先，不受单位条件影响。

搜索显示机构、方向、ORCID、抓取时间及是否命中 5 分钟查询缓存；网络失败会明确报错，不会替换成演示快照。选择候选后进入 `/live/` 查看 Agent 核验过程；该流程调用已有评分脚本，需要 Python 3，数据可能命中最长 24 小时的缓存。公共 `/scholar-api/*` 只读，不读取签名私钥或广播交易；核验后可在独立 `/claim-api/` 会话中逐篇认领、验证邮箱及通过自己的钱包存证，详见下方“学者认领与论文体检”。协作账号内的私有研究、任务和钱包声明使用另一套账号权限。既有独立 Agent 服务的接口保持兼容。

菜单中的「论文检索」进入 `/ui/papers.html`，支持主题、标题、DOI 或作者姓名，也可选择来源与学科。结构化模式并行查询，某个来源超时不阻塞其他来源，结果保留各来源信息并按 DOI、PMID、arXiv 编号及标题／年份去重。合并结果的数量仅指本次返回结果，不是整个学术库的精确总量。

语义模式使用 Sciverse 返回相关原文段落。按姓名查到的论文只是候选线索，不自动归属到某个学者。仅有可读文档标识的结果开放原文片段，分页遵循上游 Unicode 位置；图表仅允许读取已返回原文引用的图片。此流程不改变学者评分、身份认证或链上记录。

服务端在 `/scholar-api/literature/` 下提供 `health`、`catalog`、`search`、`content`、`resource` 只读接口，按 [Sciverse 官方协议](https://github.com/opendatalab/Sciverse-Agent-Tools/blob/main/openapi.yaml) 接入字段目录、结构化检索、语义检索、原文切片和图表。适配基于官方 0.14.3 协议，设有超时、缓存与访问限制；不需要安装全局 MCP 客户端。凭据缺失、额度受限和无权读原文均明确显示，不替换成演示数据。

## 独立文献源管理

直接访问 **`/admin/sources/`**，例如本地 `http://127.0.0.1:8890/admin/sources/`。该页面不出现在首页、文献检索或协作页面的导航中。它使用独立管理员口令，普通用户账号没有修改权限；隐藏网址本身不作为权限校验。

首次启动后，在服务器数据目录读取 `admin-access.txt` 中自动生成的口令，复制到管理页登录。默认位置为 `aia/app/.runtime/admin-access.txt`，该文件不会通过 HTTP 提供。部署时也可用 `AIA_ADMIN_TOKEN` 设置固定口令。口令更换后重启服务，旧管理员会话随重启失效。生产环境须设置 `AIA_ORIGIN=https://你的域名`，反向代理保留 Host 并使用 HTTPS。

各渠道卡片显示“已配置／未配置”、来源于环境还是管理页，以及接口是否已经接入。输入新值保存后立即用于新的请求，不必重启；空白不覆盖现有值。停用会保留配置，重新启用继续使用原值；“恢复环境默认”删除管理页覆盖值，并回退到部署环境变量。已保存的密钥永不回显，浏览器不使用 localStorage 保存口令或 API key。

管理页保存的覆盖值使用 AES-256-GCM 加密到数据目录的 `source-config.enc`，加密密钥独立保存在 `source-config.key`。这保护的是配置文件的单独泄漏，不是对服务器管理员隔离：部署账户仍能读取服务所需的解密密钥。备份和迁移需一起保留这两个文件及管理员口令文件，并限制数据目录访问权限。`.env` 中原有凭据继续在服务端生效；管理页不会改写 `.env` 或把凭据推到 GitHub。

已实现查询适配：Sciverse、OpenAlex、Crossref、Semantic Scholar、Europe PMC、PubMed、arXiv、DataCite、NASA ADS、Unpaywall。NASA ADS 需有效 `ADS_DEV_KEY`；Sciverse 需有效 Token；Unpaywall 需真实联系邮箱 `UNPAYWALL_EMAIL`；其他来源的密钥／联系邮箱依各服务要求配置。提供配置位置不代表凭据已经通过上游验证。CORE、OpenAIRE、Springer、EPO、The Lens 暂为配置预留，页面明确标记未接入，不会假装参与查询。

Unpaywall 在论文检索页按 **DOI** 查询开放获取状态与出版方、机构库的位置；例如选择 Unpaywall 后输入 `10.1038/nature12373`。联合检索遇到 DOI 会自动加入此源，关键词和仅作者查询不会把它当作全文搜索引擎。已收录但没有开放位置会返回书目信息并标注未发现开放获取；HTTP 404 表示该源未收录 DOI，不能等同于闭源；网络、限流和鉴权失败仍显示失败。仅提供来源报告的链接，不在服务端下载 PDF、不绕过访问权限；链接许可与版本以出版方或机构库为准。依据 [Unpaywall 官方 DOI API](https://unpaywall.org/api) 实现，联系邮箱只随服务端请求发送。

DataCite 按其 [官方稀疏字段参数](https://support.datacite.org/docs/api-queries) 只请求 DOI、标题、作者、年份、摘要、入口与成果类型，避免大批无关元数据导致查询失败；单次上游响应的 2 MB 限制继续生效。

这里管理文献与模型 API 配置，不接受钱包私钥或链上签名配置。公开文献检索只调用固定官方端点；两个评审模型槽可配置公网 HTTPS 接口，详见社区运行说明。

## 公网运行与备份

这是需要 Node 服务和磁盘的应用，不能只上传到静态网页托管。外部协作可部署到自己的服务器或支持常驻 Node 与持久磁盘的平台，前面配置 HTTPS 反向代理并保留原始 Host。启用公网前需设置固定 `AIA_ORIGIN`、备份与账号支持；本版尚无邮箱找回、机构单点登录和 ORCID OAuth。用户材料目前由服务器本地保存，不是端到端加密。

备份时停止应用，再复制完整数据目录（数据库与归档一起）。个人导出是业务记录副本，不替代原件和数据库备份。恢复时保持目录完整并指向 `AIA_APP_DATA_DIR`。

上传上限：100 个文件，单个 12 MB，总量 20 MB；PDF 最多 200 页。本地导入不会执行上传的脚本或解压运行归档；需要运行实验时，执行者在自己的受控环境完成后提交证据。

每账号最多保存 100 个研究版本，研究与交付归档合计 512 MB；每项任务最多保留 50 次交付。核查者勾选已核对文件属于署名声明，系统不会据此声称已经证明认真阅读或自动完成科研复现。

## 验证与代码位置

在仓库根目录运行 `npm test` 检查账号权限、业务状态、哈希、签名和链交易验证；`npm run test:legacy` 检查共享引擎提取对原有工作台及体检组件的兼容性。测试使用独立临时数据库，不向主网发送交易。Agent 与旧实验回归需要可用的 Python 3；Windows 默认 `python`，可以通过 `AIA_PYTHON` 配置打分解释器。

仓库新增的学者 Agent 保留独立服务，默认端口 8892，启动和只读接口见 [Agent API](../chain/AGENT_API.md)。它与账号产品共用姓名变体函数，但不共享账号数据库、不代表同一授权体系；真实用户应在本产品中管理私有研究和钱包声明。公开档案默认入口为 `/ui/`（带彩色搜索框的根目录 `xiezhi-ui/`）；另一套工作台入口为 `/workbench/`（根目录 `新ui/`），两者共享当前接口与服务端配置。

需求和接口记录见 [实施约定](../../plan/PRODUCT_IMPLEMENTATION.md)；录音来源见[协议对齐纪要](../discussions/2026-10-07_protocol_alignment/README.md)和[《AIA 区块》纪要](../discussions/2026-10-07_aia_blockchain/README.md)。搜索首页与工作台通过独立白名单提供，分别位于 `/ui/` 与 `/workbench/`；实时核验分别位于 `/live/` 与 `/workbench/live/`，共用业务逻辑。两个公开界面均不能访问科研协作账号接口；`aia/ui/` 仍停用；`aia/demo` 与 `aia/commission-demo` 保留为前期成果，不是账号的业务数据源。

## 学者认领与论文体检（2026-10-08）

默认彩色首页 `/ui/` 与工作台 `/workbench/` 均增加“查学者 / 查论文”入口。中文原名、完整拼音及姓名倒序写法视为同一匹配层级，有有效机构资料的候选优先展示；精确 ORCID、作者 ID 匹配不受此排序影响。

`/live/?demo=claim-xu` 提供明确标注的徐林森模拟材料，流程为选择档案、逐篇认领/排除/待核对、邮箱验证码、最后确认、盖章与本地链凭证。真实公开核验完成后也可继续认领，作者与最近最多 25 篇论文由服务端从 OpenAlex 读取。模拟数据不合并到真实候选中；这里生成的是用户声明及其存证，不是 ORCID OAuth、机构认证或论文作者身份认证，也不自动提高学术信誉分或发放积分。

在独立管理页 `/admin/sources/` 的“邮箱验证 · SMTP”卡片配置 SMTP_HOST、SMTP_PORT、SMTP_FROM、SMTP_USER、SMTP_PASS、SMTP_SECURE。465 端口直接 TLS 填 true，587 端口 STARTTLS 填 false；密码填邮箱服务的授权码或应用密码。保存不会发送邮件，用户点击“发送验证码”才会寄信。真实验证码不显示在页面；仅模拟案例允许本地邮件预览。验证码十分钟有效、最多五次尝试、验证后一次性消耗。邮箱可控不等于论文作者身份已认证。

认领凭证使用独立 HttpOnly Cookie 会话、CSRF 和最终确认，浏览器会话有效期为六小时。服务端将逐篇选择、验证码哈希及失败次数、待存证内容、待确认交易号保存到 `AIA_APP_DATA_DIR/claim-sessions/`，不保存原始邮箱地址或明文验证码。刷新及服务重启后，同一浏览器可在有效期内继续；清除 Cookie、切换设备或会话过期后须重新开始。证书保存在 `AIA_APP_DATA_DIR/claim-certificates/`，当前会话可下载；此前下载的文件仍可通过新的会话独立复核。

两种存证路径分别显示，不能把本地结果当作主网交易：

- **本地模拟链**：模拟案例只走此路径，公开材料完成真实邮箱验证后也可主动选择本地体验。实际 ActionRegistry 运行在进程内 Ganache（Chain ID 1337），没有公开 RPC、没有主网费用；区块增长、哈希和回执来自本地节点。节点与开发账户在 `AIA_APP_DATA_DIR/claim-local-chain/`，必须与证书一起保存，丢失该目录后不能继续核验旧的本地链凭证。
- **BOT Chain 主网**：仅对公开材料及真实 SMTP 验证开放，读取 `aia/chain/deployments/botchain.json` 中 Chain ID 677 的登记合约。用户确认公开存证与 Gas 说明，连接自己的钱包；服务端冻结当前材料哈希并生成未签名交易，用户在钱包中决定是否签名及支付 Gas。服务端没有主网私钥，不代签或自动广播。只有 RPC 核对合约、钱包、学者主题、完整调用参数、成功回执、事件与当前区块一致后才签发主网凭证。主题为 `keccak256("openalex:" + authorId)`，可与现有学者行为时间线对应。

准备存证后，材料与钱包绑定被冻结。已收到交易号时，刷新或重试只继续核验该交易，不重新要求发送；回执尚未确认时显示待确认，主网不可用时保留待办状态。若需要在钱包中加速或替换交易，使用同一钱包、相同材料并核验钱包返回的替换交易号。已签发证书的重复确认返回原证书。本地存证会先持久化内容再写链，即使上链成功但响应丢失，重试仍使用同一内容哈希。

`POST /claim-api/certificate/verify` 分别返回内容与链记录是否一致（`valid`）及文件是否与本站保存的签发档案严格一致（`issuedByThisService`）。合法的链记录本身不证明本站发过证或验证过邮箱，更不证明作者身份、论文真实性或官方 ARA Seal；第三方自己登记的文件不能据此冒充本站签发。迁移时完整保留证书目录，才能继续识别本站历史签发文件。

生产部署须为 **完整 `AIA_APP_DATA_DIR` 使用持久磁盘**，不随版本更新清空，不加入 ZIP 发布包或公开静态目录。停服后一起备份账号数据库、原件、`claim-sessions/`、`claim-certificates/`、`claim-local-chain/` 以及文献源加密配置和密钥。恢复后保持 HTTPS、`AIA_ORIGIN` 与用户访问域名一致。当前认领队列与本地链按单 Node 进程管理，同一数据目录不要同时启动多个服务副本；需要多实例时须先增加共享会话与分布式事务协调。

`/paper/` 可上传 PDF、Markdown、TXT、ARA ZIP：原始上传最多 12 MB，解包总计最多 20 MB、100 个文件。检查原始 PAPER.md、logic、src、trace、evidence，以及主张到证据的引用和可比较的结构化指标。服务自动生成的导航不算原稿已经符合 ARA；普通 PDF 会列出缺失材料。两份完全虚构的案例支持下载 ZIP、修改后再次上传比较。原件检查结束后删除，报告只在当前会话保留一小时；可下载 JSON 保存报告。这里只做材料结构与证据预检，不执行上传代码，不宣称 ARA 官方 Seal 或科研真假裁定。

部署新增依赖为 ganache、nodemailer，需在仓库根目录重新 `npm ci --omit=dev`。必须携带 `aia/paper-checkup/` 的 fixtures（只供服务端读取）及 `aia/live/claim-flow.js/css`、`xiezhi-ui/entry.css`；不要只替换 HTML，也不要公开运行数据目录。API 前缀为 `/claim-api/` 与 `/paper-api/`，整站反向代理保持同源即可。
